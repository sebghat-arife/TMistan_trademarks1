# Schema notes

```
gazettes 1 ──── * trademarks 1 ──── * trademark_images ──── Supabase Storage
                     │                        │
                     │                        └── status: matched | unmatched | ambiguous | needs_review
                     │
                     ├── review_status: unreviewed | reviewed | needs_correction | verified
                     └── audit_logs (trigger, per-field diff, actor from JWT)

import_jobs 1 ──── * import_job_items      (excel | images; never silent)
user_roles                                 (admin | editor | viewer  → is_admin())
admin_* RPCs (0400)                        (SECURITY DEFINER, admin_assert() first — the Import Center's only write path)
```

## Stable identifier: `serial_number`

Serial numbers are printed as `<gazette>-<nnn>` (`1011-002`) and are unique across the registry, so
0400 adds a guarded unique index `trademarks_serial_number_key` (created only when no duplicates
exist; otherwise a WARNING lists them) next to the original `(official_gazette_number, serial_number)`
key. `serial_canonical(text)` (`' 1011_02 '`, `'۱۰۱۱-۰۰۲'`, `'IMG_1011-002'` → `'1011-2'`) backs the
expression index used to match image file names; matching tiers are exact → normalized → numeric and
never guess between two candidates.

## Why the gazette FK is on the natural key

`trademarks.official_gazette_number` already exists and the Excel importer already writes it.
Making it a foreign key to `gazettes.gazette_number` (with a `BEFORE INSERT` trigger that creates
the gazette row on demand) means:

- the existing importer keeps working with zero changes;
- `select … from trademarks join gazettes using (…)` is possible;
- there is no second nullable `gazette_id` column to keep in sync.

## Normalisation (`normalize_text`)

Applied identically at index time (generated columns) and query time (inside the RPC):

| Input | Normalised |
|---|---|
| `COCA-COLA  Company!` | `coca cola company` |
| `Café Ünïcode` | `cafe unicode` |
| `شركة كابل ۱۲۳` (Arabic ك, Persian digits) | `شرکه کابل 123` (Persian ک, ASCII digits) |
| `1011-002` | `1011 002` |

So `شركة` (Arabic kaf/ta-marbuta) finds `شرکه` (Dari spelling) and `1011002`, `1011-002`, `1011 002` all match.

## Search ranking (`search_trademarks`)

score = max of:

| Signal | Weight |
|---|---|
| exact normalised mark or serial | 10 |
| mark starts with query | 5 |
| exact applicant | 4 |
| `ts_rank_cd` on weighted tsvector (mark A, serial A, applicant B, attorney C, goods D), prefix query | ×3 |
| trigram similarity of mark | ×3 |
| trigram similarity of applicant | ×1 |

Fuzzy (`%` operator, `pg_trgm.similarity_threshold` default 0.3) is on by default and can be turned
off per query (`p_fuzzy=false`). Sorting options: relevance (only when there is a query), newest,
oldest, mark A→Z / Z→A, serial (gazette desc then serial).

Pagination is `LIMIT/OFFSET` capped at offset 10 000; the RPC raises a clear error beyond that.
When the table reaches hundreds of thousands of rows, switch deep paging to keyset on
`(publication_date, id)` — the function signature can stay the same by adding a `p_after` cursor.

## Image storage layout

```
trademark-images/
  1011/1011-001-3f9a2c7b1e0d.png  Import Center + Python importer: <gazette>/<serial>-<sha256[0:12]>.<ext>
                                  (content-addressed: identical bytes → same path → "unchanged"; a corrected
                                  picture → new path + new URL, the superseded object is removed after the
                                  row has been re-pointed)
  1011/1011-001.png               legacy path of images uploaded before migration 1000 (kept until replaced)
  1011/1011-002_mark_print-<h>.png other image types (Python importer)
  thumbs/1011/1011-001-<h>.webp   ≤320 px WebP, generated by the Python importer only
  _unmatched/1011/<original name> parked files awaiting manual review (Python importer only; the
                                  Import Center never uploads unmatched files — it reports them)
```

Uniqueness: `(storage_bucket, storage_path)` and `(trademark_id, image_type, content_hash)`.

## Room left for Phase 3 (similarity / AI)

- Text similarity already works via `pg_trgm` (`similar_trademarks`).
- Visual similarity: add `alter table trademark_images add column embedding vector(512)` +
  an HNSW index (pgvector is available on Supabase) and a `similar_images(p_image_id)` RPC.
  No existing column or function needs to change.
- AI suggestions: store them in a separate `suggestions` table with `status` (proposed / accepted / rejected)
  and apply through the same admin edit path so the audit log captures who accepted what.

## Data management additions (migration 0600)

- `trademarks.registration_number`, `trademarks.application_number` — columns 13–14 of the official
  Excel structure, stored verbatim (text).
- `trademarks.created_by_job_id`, `trademark_images.created_by_job_id` — the import job that **created**
  the row (set once, never overwritten; back-filled from `audit_logs` INSERT entries). `import_job_id`
  keeps meaning "last job that touched the row". Together they make delete-by-batch reliable:
  *created by job X and not modified since* vs. *created by X but modified later* vs. *only updated by X*.
- `admin_actions` — operation-level audit log (actor, action, target ids, serials, Storage paths, job,
  counts, status, details). `admin_actions` and `audit_logs` are append-only (no grants + trigger).
- `storage_cleanup_queue` — Storage objects whose database rows were deleted; removed by the admin
  browser through the Storage API, `failed` entries keep the error and are retried.
- Public API: `anon`/`authenticated` hold column-level SELECT on `trademarks`/`trademark_images` for the
  public columns only (`TRADEMARK_PUBLIC_COLUMNS` / `TRADEMARK_IMAGE_PUBLIC_COLUMNS` in
  `web/src/lib/database.types.ts` mirror the grant lists). Attorney, review fields and source
  file/sheet/row are administrator-only; `search_trademarks` & co. no longer return the attorney.
- See `docs/ADMIN_DATA_MANAGEMENT.md` for the functions and the safety model.

## Search by application / registration number (migration 0700)

- Function-only: `search_trademarks()` is dropped and re-created with two extra optional parameters,
  `p_application_number` and `p_registration_number` (substring match on `normalize_text(...)`, so
  `77821` finds `R-77821` and Persian / Arabic-Indic digits work). The keyword search (`p_query`) also
  matches those two columns; an exact number match ranks 9 (just under an exact mark/serial match, 10).
- Why drop first: adding parameters to an existing function creates a second overload and PostgREST
  can then not choose between them — every search would fail. After 0700 exactly one
  `search_trademarks` exists; the 0600 call shape (15 arguments) still resolves.
- No table, column, index, policy or row changes; `trademark_search_result` is unchanged. Requires 0600.
- The web app probes the capability once per session (`searchByNumbersSupported`): a call with the new
  parameters either returns or fails with `PGRST202`; on failure the two fields are disabled
  (*Not available yet*) and searches are retried without them (`numbersIgnored`).

## Contact & Feedback inquiries (migration 0800)

- One new private table `public.contact_requests` (`id`, `created_at`, `inquiry_type`, `full_name`,
  `email`, `organization`, `subject`, `message`, `details jsonb`, `locale`, `page_url`, `user_agent`,
  `ip_hash`, `status new|in_progress|closed|spam`, `admin_note`, `handled_by`, `handled_at`) with CHECK
  constraints on every length/enum. RLS is enabled with **no policies and no grants** — the table is
  invisible to the API; only the `security definer` functions touch it.
- Public functions (anon + authenticated): `contact_form_status()` (capability probe) and
  `submit_contact_request(p_inquiry_type, p_full_name, p_email, p_subject, p_message, p_organization,
  p_details, p_locale, p_page_url, p_honeypot)` → `{id, received_at}`. Validation errors use SQLSTATE
  `22023` with a user-facing message, rate limits use `TM429` (5/h per e-mail, 10/h per hashed IP,
  60/10 min overall). `details` is whitelisted to the known category keys and clipped to 1000 chars
  each. The IP (from `cf-connecting-ip` / `x-forwarded-for` / `x-real-ip`) is stored only as a salted
  SHA-256 hash (`sha256()` built-in — no extension needed).
- Admin functions (authenticated + `admin_assert()`): `admin_contact_counts()`,
  `admin_list_contact_requests(p_status, p_type, p_query, p_limit ≤ 200, p_offset)` (rows +
  `total_count`), `admin_get_contact_request(p_id)`, `admin_update_contact_request(p_id, p_status,
  p_admin_note)` (sets `handled_by/handled_at`, logs `contact.update` through `admin_record_action`).
- Requires 0400 and 0600; independent of 0700. Additive and idempotent. See `docs/CONTACT.md`.

## Data correction requests (migration 0900)

- Two new private tables. `public.correction_requests` (`id`, `reference` unique `CR-XXXXXXXX`,
  `created_at`, `updated_at`, `request_type incorrect_name|classification|image|publication_reference|duplicate|other`,
  `full_name`, `email`, `related_record`, `trademark_id → trademarks(id) on delete set null`,
  `description`, `locale`, `page_url`, `user_agent`, `ip_hash`, `status
  received|under_review|more_info_needed|resolved|closed_no_change`, `internal_note`, `public_note`,
  `handled_by`, `handled_at`) and `public.correction_request_events` (`request_id`, `created_at`,
  `actor_id`, `from_status`, `to_status`, `note`) — the status history. RLS on, **no policies, no
  grants**: invisible to the API, touched only by `security definer` functions.
- Public functions (anon + authenticated): `correction_form_status()` (capability probe),
  `submit_correction_request(p_request_type, p_full_name, p_email, p_description, p_related_record,
  p_locale, p_page_url, p_honeypot)` → `{id, reference, received_at, upload_until}` (validation
  `22023`, rate limits `TM429`: 5/h per e-mail, 10/h per hashed IP, 60/10 min overall; honeypot
  returns a fake success; a `related_record` equal to a serial number links `trademark_id`),
  `correction_request_status(p_reference, p_email)` → `{reference, status, request_type, created_at,
  updated_at, public_note}` or `null` (both values must match), and `correction_upload_allowed(p_name)`
  used by the Storage policy (`<request-uuid>/<8–40 chars>.(jpg|jpeg|png|pdf)`, request younger than
  15 minutes, fewer than 3 files, fewer than 40 uploads/hour in the bucket).
- Admin functions (authenticated + `admin_assert()`): `admin_correction_counts()`,
  `admin_list_correction_requests(p_status, p_type, p_query, p_limit ≤ 200, p_offset)` (rows +
  `total_count`), `admin_get_correction_request(p_id)` (row without `ip_hash` + `events` + `files`
  from `storage.objects`), `admin_update_correction_request(p_id, p_status, p_internal_note,
  p_public_note, p_trademark_serial)` (no return to `received`; serial must exist; writes an event
  row and `handled_by/handled_at`; logs `correction.update` through `admin_record_action`).
- Storage: private bucket `correction-evidence` (5 MB, JPEG/PNG/PDF) with three policies on
  `storage.objects` — `tmistan visitor upload correction evidence` (insert, anon + authenticated,
  gated by `correction_upload_allowed`), `tmistan admin select/delete correction evidence`
  (authenticated + `is_admin()`). Administrators read files through signed URLs only.
- Requires 0400 and 0600; independent of 0700 and 0800. Additive and idempotent. See
  `docs/CORRECTIONS.md`.

## Image re-upload fix (migration 1000)

Deleting an image (`admin_delete_images` & co.) only *queues* the removal of its Storage object in
`storage_cleanup_queue`; the browser removes queued objects later. Until 1000 a picture re-uploaded
for the same serial re-used the queued path, so a later queue run deleted the new file. Functions
(all `security definer`, `admin_assert()`):

- `admin_register_images(p_job_id, p_items)` — same contract as 0600; additionally cancels queued
  removals (`pending`/`failed` → `skipped`) of every path/thumbnail it registers.
- `admin_storage_cleanup_list(p_status, p_limit)` — marks queued entries whose path is referenced by
  a current `trademark_images` row as `skipped` *before* listing, so the browser can never be handed a
  live file to delete. `admin_storage_cleanup_mark` keeps the note for `skipped`.
- `admin_trademark_images_lookup(p_trademark_ids uuid[])` (≤ 1000 ids) — current image rows of the
  given trademarks (id, type, status, method, paths, `content_hash`) for upload planning.
- `admin_cancel_storage_cleanup(p_paths, p_note)` — internal helper, not callable through the API.
- One-off: queue entries that already point at a live image are set to `skipped`
  (`last_error = 'skipped by migration 1000: …'`). No trademark/image row and no Storage object is
  touched. Requires 0600; independent of 0700–0900; idempotent.
